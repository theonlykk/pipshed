# ADR-069: Full-Book Best Quotes via Slot Direction Classification

**Status:** Accepted  
**Date:** 2026-07-01  
**Context:** ADR-066/068 restored Layer-0-only `best_quotes` using `layer0_bid_price` / `layer0_offer_price`. Operators need cross-instance extremes that include resting add-next and exit limits, not just Layer 0. ADR-068 deferred this pending direction classification. Fxmatrix-side investigation (ExecutionEngine.mqh, ADR-043) confirmed the classification rules below.

## Direction homogeneity invariant (fxmatrix)

Under normal runtime, all layers in one slot's `g_inventory_*` array share identical `.direction`:

- Layer 0: direction from fill `deal_type` (`DIRECTION_BUY = 1`, `DIRECTION_SELL = -1`, LayerStruct.mqh).
- Layer 1+: `L.direction = L0.direction` (HandleEntryFill inheritance).
- Add-next: `PlaceNextEntryLimit` uses `prev_layer.direction`.
- Layer 0 gate: `SameDirectionInventoryExists()` (ADR-043) blocks same-direction Layer 0 reload on Phase 3 resume; does not alter per-layer direction assignment.

Telemetry emits `layer_detail[].direction` as integer `%d` matching the struct (TelemetryEngine.mqh `SerializePodJSON`).

## Decision

### 1. Add `full_best_quotes` to aggregate endpoint (additive)

New response key alongside unchanged `best_quotes` (Layer-0-only, diagnostic / backward compatible):

```json
"full_best_quotes": {
  "EURUSD": {
    "best_bid": 1.08450,
    "best_offer": 1.08520,
    "direction_conflict": false
  }
}
```

Per symbol, cross-instance max-bid / min-offer over:

| Order type | Classification |
|------------|----------------|
| Layer 0 | Unambiguous: `layer0_bid_price` → bid, `layer0_offer_price` → offer |
| add_next | Same side as slot inventory direction (inherits layer direction) |
| exit_orders[] | Opposite of slot inventory direction |

Slot inventory direction: sole distinct value in `layer_detail[].direction` for that symbol on that instance. Flat pods (zero layers): `slot_direction = None` — Layer 0 still merged; add_next/exit skipped.

### 2. `direction_conflict` safety flag

If a slot's layers contain more than one distinct non-null `direction` value, set `direction_conflict: true` for that symbol and **do not** classify add_next or exit orders from that instance (Layer 0 also skipped for that instance in `full_best_quotes`). Known edge cases — not fixed here:

1. **ADR-014 opposing-quote race** — both MM bid/offer fill before cancel; deeper layer inherits L0 direction while broker may hold opposite position.
2. **Corrupt state reload** — StateEngine restores per-layer direction without cross-layer validation.

Detection only; root-cause fix remains out of scope (fxmatrix forensic task).

### 3. Dashboard widget

`renderAggregate()` reads `full_best_quotes` for displayed bid/offer/spread. Appends amber `⚠ mixed direction` suffix when `direction_conflict` is true. `best_quotes` remains in API response unchanged.

## Consequences

- **Positive:** Widget reflects full resting book (Layer 0 + add_next + exits) without EA telemetry changes.
- **Positive:** `best_quotes` preserved for Layer-0-only comparison and backward compatibility.
- **Positive:** Non-uniform direction flagged rather than silently misclassified.
- **Negative:** Aggregate spread interpretation caveat from ADR-066 still applies (independently managed pods, not a unified book).
- **Negative:** `direction_conflict` does not distinguish ADR-014 race vs corrupt reload — both flag the same way.
