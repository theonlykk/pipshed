# ADR-073: Per-Pod Telemetry Detail on Instance Pod Cards (Part 2)

**Status:** Accepted  
**Date:** 2026-07-01  
**Context:** ADR-065 Part 1 added cross-instance aggregate widgets (system alerts banner, macro exposure, best working quotes) and explicitly deferred per-pod enrichment to Part 2 per ADR-064 / Gemini ruling. The EA already emits enriched fields on each live payload — `layer_detail[]`, `ldak_status`, `ldak_size_mult`, and per-symbol `working_orders` — but the instance-scoped pod cards rendered only four summary fields (label, layer count, PnL, distance-to-target).

## Decision

### 1. Scope (ADR-065 Ruling 2 / Part 2)

Extend `renderPod()` in `templates/dashboard.html` for the **currently selected instance** only. The three `#pod-grid` slot cards (`#pod-0` … `#pod-2`) gain a conditional detail section when `pod.layers > 0`. No backend changes; no new endpoints; no new telemetry fields.

**Rendered on each active pod card:**

| Source field | Presentation |
|--------------|--------------|
| `pod.ldak_status` | Colored pill badge: `pass` (green), `clamp` (amber), `refuse` (red) |
| `pod.ldak_size_mult` | Appended to badge label when status is not `pass`, e.g. `clamp (0.62)` |
| `pod.layer_detail[]` | Compact table: direction (BUY/SELL), `entry_price`, `exit_price_fixed`, `lot_size` |
| `layer.resting_exit_missing` | Red `NO EXIT` pill — unmissable indicator for missing resting exit order |
| `layer.is_toxic` | Amber-bordered `TOXIC` pill (ADR-040 named condition) |
| `working_orders[symbol].add_next_price` | One-line summary when present |
| `working_orders[symbol].exit_orders[]` | Compact count + nearest price — **not** the full array inlined |

**Preserved unchanged:** the four base fields (label, layers count string, PnL via `setPnl`, distance-to-target). Aggregate widgets, `fetchAggregate()` / `renderAggregate()`, closed-trades logic, and `app.py` are untouched.

### 2. What is summarized vs. fully rendered

- **`layer_detail[]`:** fully rendered — one table row per layer (typically ≤ inventory depth).
- **`exit_orders[]`:** summarized only — `"N exits, nearest at X.XXXXX"`. Nearest is direction-aware: min price for long slots (`direction === 1`), max for short (`direction === -1`). Rationale: exit arrays can grow with partial fills; inline listing would overflow the compact card layout.
- **`add_next_price`:** single scalar line when non-null.

### 3. Layout trade-off resolution

Adding per-layer rows makes active pod cards taller than the pre–Part 2 four-line summary. **Grid restructure rejected** — the 3-column `#pod-grid` layout is retained.

Instead, `#pod-grid` receives `align-items: start`. This overrides CSS Grid’s default `stretch` alignment so each card sizes to its own content and sits at the top of its cell rather than stretching to match a busier neighbor. Cards may differ in height within the row; that is acceptable and intentional.

Detail typography: 11px mono table, 10px LDAK badge, tight row padding — consistent with existing `--font-mono` conventions and smaller than the 28px layer-count headline.

### 4. Zero-layer behavior

When `pod.layers <= 0`, the `#pod-N-detail` container is cleared. Empty slots and flat pods retain the existing summary-only appearance (label `—`, `"0 layers"`, etc.).

## Consequences

- **Positive:** Operators see per-layer inventory, LDAK gate state, and resting-order summary on the instance they are watching — without a second fetch or backend work.
- **Positive:** `resting_exit_missing` and `is_toxic` are visually distinct (red fill vs amber border), not color-only.
- **Positive:** `align-items: start` avoids false visual parity when one pod has many layers and neighbors are empty.
- **Negative:** Active pods with many layers produce tall cards; mobile stacking (ADR-070) mitigates horizontal squeeze but not vertical scroll length.
- **Neutral:** `working_orders` is keyed by symbol on the live payload; `render()` passes `data.working_orders[sym]` into `renderPod()` — minimal call-site change only.

## Files changed

- `templates/dashboard.html` — `#pod-grid` alignment, pod detail CSS/HTML containers, extended `renderPod()`, `render()` call-site pass-through of `working_orders`
- `ADR-073.md` — this document
