# ADR-068: Restore Layer-0 Best Quotes After ADR-067 Field Rename

**Status:** Accepted  
**Date:** 2026-07-01  
**Context:** ADR-066 added `best_quotes` to `GET /api/telemetry/aggregate`, reading `bid_price` and `offer_price` from each symbol's entry in `working_orders`. ADR-067 (fxmatrix repo) renamed the `working_orders` shape: top-level `bid_price` / `offer_price` were replaced by layer-scoped fields (`layer0_bid_price`, `layer0_offer_price`, plus `add_next_*` and `exit_orders[]`). After that rename, `telemetry_aggregate()` continued to call `.get("bid_price")` and `.get("offer_price")`, which always returned `None`. The dashboard Best Working Quotes widget therefore showed empty/null quotes despite live Layer-0 orders in Redis.

## Decision

### 1. Restore Layer-0 field reads in `telemetry_aggregate()`

Change the two field reads in the `best_quotes` loop from:

- `quote.get("bid_price")` → `quote.get("layer0_bid_price")`
- `quote.get("offer_price")` → `quote.get("layer0_offer_price")`

No other logic changes: max-bid / min-offer comparison, `None` handling, instance iteration, and response shape remain exactly as in ADR-066.

### 2. Scope remains Layer 0 only

`best_quotes` continues to reflect **Layer-0 resting quotes only**. This ADR does **not** expand aggregation to:

- `add_next_bid_price` / `add_next_offer_price`
- prices inside `exit_orders[]`

That scope was intentionally deferred. Including add-next or exit tickets would require a direction-classification design that does not exist today.

## Open design question (future ADR)

Exit orders cannot be reliably classified as bid-side vs offer-side without one of:

1. **Direction field per exit ticket** — add explicit bid/offer (or buy/sell) direction to each exit ticket in EA telemetry; or
2. **Correlate with `layer_detail[]`** — infer direction by matching exit tickets to layers; this breaks down when a layer has multiple exit tickets from partial fills.

Until that decision is made, aggregate `best_quotes` must not attempt to merge add-next or exit prices. A follow-up ADR should define direction classification before any scope expansion.

## Consequences

- **Positive:** Best Working Quotes widget works again against post–ADR-067 Redis state without EA or dashboard changes.
- **Positive:** Minimal, targeted fix — two field renames, no behavioral expansion.
- **Negative:** Cross-instance snapshot still excludes add-next and exit resting prices; operators see Layer-0 extremes only.
- **Neutral:** ADR-066 interpretation caveat (negative aggregate spread across independently managed pods) still applies.
